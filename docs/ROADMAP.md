- At most one release-scoped milestone may be active at a time.
- Define the user-visible outcome, compatibility boundary, security impact, and completion gate before implementation.
- Preserve current filesystem, encoding, mutation, backup, execution, transport, and source-intelligence boundaries unless a milestone explicitly changes them.
- Keep public MCP concepts compact and difficult to misuse.

## Active milestone — Source Intelligence structural reliability

**Purpose:** Give an LLM a concise, dependable first map of an unfamiliar project, then let it locate and inspect only the source relevant to its task. Source Intelligence is a set of **read-only evidence and navigation tools**, not an agent, compiler or semantic decision engine. The **LLM** interprets the user request, selects queries, evaluates relevant files and decides what to inspect or provisionally exclude. **Scripthold** returns bounded source facts, locations, supported relations, exact excerpts and honest limitations; it neither chooses the edit site nor judges relevance to the user's task. The agent remains free to use `source_*`, `grep_text_files`, or direct reads; spontaneous tool selection is not a qualification target.

**Released baseline (4.0.1):** `source_symbols` provides `digest`, `outline`, `find`, and fingerprint-verified `show`; `source_query` provides supported structural search, relationships, and context. `outline` defaults to `presentation: "tree"`; callers needing the historical top-level `files` and `symbols` request `presentation: "detailed"`. The separate filesystem `tree` tool describes paths, not source-symbol ownership. See the [tool reference](../TOOLS.md#source_symbols) and [capability matrix](LANGUAGE_CAPABILITIES.md) for the actual contracts. Post-release parser fixes in Git are not proof that an already running connector has been updated.

### Qualification method and evidence limits

**Project-navigation checks** begin with a realistic maintenance question and complete reads of the selected original sources *before* querying the development handler. Immutable upstream revisions, independent grep/source oracles, plausible neighboring and unrelated files, bounded digest/find/query responses, fingerprint-bound excerpts and truthful coverage are checked together. A PASS certifies only the tested navigation task, not an entire grammar, hidden dependencies, program execution or an LLM's choice to call the tool. The [project-first checklist](DEVELOPMENT_CHECKLIST.md#source-intelligence-project-first-qualification) defines the reusable acceptance criteria. Local original snapshots remain outside tracked files; provider-specific Go tests and Git history retain implementation and verification evidence.

**Retrospective selected-file declaration inventories** are a separate, stricter gate: 22 project cases, 77 fully read original files and 1,913 independently annotated declarations within the stated supported structural syntax. These inventories compare the complete detailed outline against original-source names, native kinds, owners, lines, duplicate/conditional alternatives and negative non-declarations. They are **not** whole-repository or whole-language certification.

### Known limitations and verification boundaries

These caveats describe **current development-tree behavior and unresolved work**, not a list of completed language campaigns. Resolved parser changes belong in the [Unreleased changelog](../CHANGELOG.md#unreleased); the [capability matrix](LANGUAGE_CAPABILITIES.md) and [tool reference](../TOOLS.md#source_symbols) describe supported navigation.

- **ECMAScript-family variable classification is lexical, not runtime type inference.** A binding is indexed as an arrow-function declaration only when its own supported initializer directly declares an arrow; arrows inside object values, calls, conditional alternatives or type annotations do not promote the enclosing variable to a function. In TypeScript, a completely parenthesized direct arrow with a simple `as` or `satisfies` type name also retains its function kind; complex assertion types and compound runtime expressions remain conservatively excluded. A variable initializer split immediately after `=` or a direct `=>` is read as one declaration, preserving the supported function kind and source excerpt. Directly assigned, ungrouped `function`, `async function` and generator expressions with a complete parameter list and body are also indexed as callable `function-expression` bindings; nested, immediately invoked, conditional and compound function-valued expressions remain ordinary values. Parenthesized function-expression wrappers and other continuation syntax can still need direct inspection. Dynamic values, unsupported expressions and runtime type resolution remain outside this subset.
- **TclOO declaration navigation is limited to explicit class bodies.** Classes created with `oo::class create` and their directly declared members are indexed with lexical class ownership; imported `class create` aliases, `oo::define` mutations, inheritance/mixin semantics, indirect command invocation and Tcl execution are not resolved. A recognized subset must not be mistaken for full Tcl/TclOO grammar coverage.
- **JScript.NET returned-object navigation is lexical, not runtime alias resolution.** Direct identifier-key `function` members in nested returned object literals have navigable lexical owners, but assigning an immediately invoked function's result to a variable does not establish that variable as the object's semantic owner. Quoted/computed keys, arrow-valued members, and dynamic aliases remain outside this structural subset.

- **Selected scope is not full grammar coverage.** Even a completely inventoried selected file does not prove unrelated files, every language construct, full ownership semantics, inferred relations, or runtime correctness. In GraphQL, supported top-level named fragments and schema directive definitions are navigable as `section` declarations (`nativeKind: fragment` and `nativeKind: directive`), with direct named directives, supported argument lists, optional `repeatable`, and named locations. Direct line-form enum values, with simple optional annotations, are navigable as `constant` members (`nativeKind: enum-value`) under their owning enums; inline and complex multiline values remain outside this lexical subset. Anonymous operations, directive/field argument semantics, fragment-spread resolution and query selections remain outside the selected supported-declaration inventory. A successful `coverageComplete` result means the requested files were processed within the analyzer's declared scope, not that all declarations, call sites, or dependencies were found. Some larger original Lua and D files, MQL4 server scripts, and complex VHDL forms remain partially supported. A shell script with no function declarations can legitimately return no symbols. Keep partial or excluded files distinct from passing maintenance scenarios.
- **Indented Sass exposes declaration lines, not full property blocks.** Fingerprint-verified `source_symbols.show` for a Sass selector currently returns its declaration line; callers examining the style properties must use a bounded targeted source read. This is not full Sass block/selector ownership or compilation support.
- **Document/configuration providers have narrower indexes.** Direct TOML triple-quoted basic and literal multiline key values now retain their complete lexical source range, so `show` can inspect the original full description without reporting headings or assignments embedded in that string as declarations; nested/compound multiline value expressions remain outside this verified subset. JSON package manifests expose supported object-key paths, including repeated nested export keys, but do not resolve conditional module exports or execute builds. Malformed strict JSON now reports incomplete coverage instead of accepting recoverable keys as proof of a valid document; already identified keys may still be navigable as partial evidence. JSON with comments (JSONC), such as some editor launch configurations, is not strict JSON and requires direct inspection rather than assuming normal JSON navigation. YAML workflow navigation now retains the complete source range of directly declared literal/folded block scalars such as `run: |`, including supported indentation indicators, and keeps subsequent sibling keys discoverable. It still reports incomplete coverage for list/step semantics: matching a `run` or `uses` key does not establish a distinct step identity, and related `justfile` or shell commands require direct source inspection. Nix indexes supported direct outer `let` bindings while excluding nested attribute-set keys, function-local bindings, and examples inside indented multiline strings from top-level declarations; skipped nested assignments receive an incomplete-coverage diagnostic. It still does not index root or result attribute sets, and indentation plus bounded brace navigation is not a complete Nix parser. Protocol Buffers indexes named messages, enums, services, fields and RPCs, plus directly declared `NAME = integer;` enum values with verified ownership. Direct single-line field declarations now preserve their source text through the terminating `;`, including bracketed inline options; unresolved or multiline suffixes are marked partial, not reconstructed. Inline enum members and per-member option lists remain outside the supported index. Directly declared `extend` blocks and their fields are navigable as lexical scopes, but external extended types are not resolved or assigned semantic ownership. Invalid dotted `message`, `enum`, and `service` declarations are excluded with explicit incomplete-coverage diagnostics; a completed scan is not exhaustive grammar recognition. OpenAPI YAML route navigation indexes operations with explicit `operationId` and method/path fallbacks for directly declared `paths` entries without one; it does not validate request semantics or resolve JSON/complex YAML structures. Ansible `import_playbook` references are not followed or treated as tasks. These tools do not evaluate Nix expressions, resolve OpenAPI references, or execute imported playbooks.
- **Large Zig source files may remain partially indexed.** In the original zmx project, `src/main.zig` reports incomplete selected-file coverage. The qualified navigation task uses the narrower configuration, POSIX helper, test-entry, and unrelated-label scope, with an independent direct read of the main entry point; it does not claim complete indexing of the larger file.
- **Some component forms remain conservatively partial.** Vue Options API shorthand methods and shorthand `computed` getters in exported options objects are now indexed in the development tree, with original Vuetify examples checked by a current-HEAD RED/GREEN regression. Dynamic option spreads, function-valued computed entries and computed `get`/`set` object descriptors remain outside that supported scope; the separate original `sortgroupcity` source has not been rechecked. Svelte 5 direct object-destructured `$props` bindings (for example `copyCode`) are now indexed in the development source, including aliases, defaults and rest bindings; nested/computed patterns are not fully inferred. The selected Vue/Svelte tasks do not prove complete component APIs or browser behavior.
- **Some language constructs are intentionally conservative.** The Ada analyzer explicitly marks task/protected bodies and declarations with unsupported scope coverage as incomplete. In the additional Universal Ctags Ada fixtures, package declarations are navigable, but task/protected member relationships and generic instantiation semantics still require direct source inspection; separate Sample Programs Ada files are standalone search/shortest-path examples. The Tcl analyzer indexes named `proc` commands and supported `namespace eval` scopes. The development tree now also indexes explicit TclOO `oo::class create` classes and their directly declared constructors, methods, and destructors with lexical ownership. The earlier MAL Tcl procedure-navigation checks alone do not certify complete class APIs, imported aliases, dynamic commands, or runtime behavior. Scala XML's selected 87-declaration audit covers package, type and type-member declarations, not function-local declarations (including local classes/objects and nested functions), macro expansion or Scala compiler semantics. Swift enum cases and directly nested local function declarations are now indexed, but local declarations inside deeper control-flow or closure scopes, arbitrary function-local variables, conditional compilation semantics and full Swift grammar are not certified; `coverageComplete` must not be interpreted as compiler validation. Nested or macro-generated Common Lisp/Clojure/Emacs Lisp forms, advanced D and Lua syntax, complex VHDL types, ambiguous Ruby method bodies, preprocessor directives, generic/type inference, and dynamic dispatch are not universally resolved. Do not manufacture symbols, ownership, callable bodies, or project-wide dependencies where analysis lacks evidence.
- **Structural links are not execution semantics.** The additional COBOL Universal Ctags cases navigate named programs, sections and paragraphs in original printer and embedded-SQL fixtures, while SQLCA data layout and `EXEC SQL INCLUDE SQLCA` must be checked by direct reads; no embedded-SQL dependency resolution or execution is inferred. The separate Rosetta Code COBOL examples cover standalone CSV and graph tasks rather than one application. The additional Assembly NASM interpreter navigation locates named labels in selected files; include references and macro definitions require direct source inspection, and the separate x86-64 Sample Programs examples do not form one application. In the additional Perl checks, named subroutines can be located in related MAL modules, but imports, calls and namespace dispatch must be checked against original source; the separate Sample Programs project contains alternative sorting snippets, not an interdependent application. In the additional Elixir checks, the Mix entrypoint and MAL cross-module calls also need direct source inspection; the independent Sample Programs project contains standalone sorting examples. The additional Tcl MAL interpreter checks directly read `source` imports alongside its indexed procedures, while the separate Sample Programs Tcl examples are independent search/graph programs, not one application. Adjacent Go/TypeScript/R/PHP code, XML/MSBuild imports, GraphQL resolvers, stylesheet consumers, HTML code-behind, and configuration overrides may be inspected directly, but providers do not automatically establish every cross-file semantic relationship. In the additional CodeIgniter and Joomla PHP/HTML navigation checks, static HTML IDs and named PHP declarations are findable, while view/template selection and JavaScript DOM links require direct source inspection rather than inferred source-query relations. No original-project execution, compilation, database query, cloud operation, UI rendering, numerical simulation, or runtime correctness is certified by this milestone.
- **Development and installed servers differ.** An installed 4.0.1 connector may predate Git changes. Confirm discrepancies against current development handlers rather than treating an older result as a current-HEAD defect. Fingerprint-bound `show` can correctly refuse oversized source regions with `LIMIT`; narrow the requested declaration or use an authorized targeted source read instead of silently raising resource bounds.

### Next work

1. **Repair proven navigation defects:** Reproduce misleading or missing edit targets on development HEAD before changing a parser. Prioritize fabricated symbols or links (P0), missed significant declarations and misleading completeness (P1), then inefficient but correct navigation (P2); do not chase unsupported compiler semantics without a demonstrated need. The Vue 2 case above remains a candidate, not a confirmed new development-HEAD regression.
2. **Keep response and release gates separate:** Recheck concise output only when behavior or compatibility changes, using the [on-demand checklist](DEVELOPMENT_CHECKLIST.md#source-intelligence-response-contract-qualification-on-demand). Standalone MCP, transport, cross-platform and release qualification require separate authorization. Do not execute original third-party projects.
