- Define the user-visible outcome, compatibility boundary, security impact, and completion gate before implementation.
- Preserve current filesystem, encoding, mutation, backup, execution, transport, and source-intelligence boundaries unless a milestone explicitly changes them.

## Active milestone — Source Intelligence structural reliability

**Purpose:** Give an LLM a concise, dependable first map of an unfamiliar project, then let it locate and inspect only the source relevant to its task. Source Intelligence is a set of **read-only evidence and navigation tools**, not an agent, compiler or semantic decision engine. The **LLM** interprets the user request, selects queries, evaluates relevant files and decides what to inspect or provisionally exclude. **Scripthold** returns bounded source facts, locations, supported relations, exact excerpts and honest limitations; it neither chooses the edit site nor judges relevance to the user's task. The agent remains free to use `source_*`, `grep_text_files`, or direct reads; spontaneous tool selection is not a qualification target.

**Released baseline (4.0.1):** `source_symbols` provides `digest`, `outline`, `find`, and fingerprint-verified `show`; `source_query` provides supported structural search, relationships, and context. `outline` defaults to `presentation: "tree"`; callers needing the historical top-level `files` and `symbols` request `presentation: "detailed"`. The separate filesystem `tree` tool describes paths, not source-symbol ownership. See the [tool reference](../TOOLS.md#source_symbols) and [capability matrix](LANGUAGE_CAPABILITIES.md) for the actual contracts. Post-release parser fixes in Git are not proof that an already running connector has been updated.

### Qualification method and evidence limits

**Retrospective stricter audit:** The 22 passing second-half scenarios were previously assessed for bounded task-oriented navigation, not exhaustive recognition of every declaration in their selected files. The stricter review reads the entire selected original source *before querying Scripthold*, independently inventories all declarations expected within the declared syntax scope, then checks the full detailed outline for omissions, invented declarations, incorrect identities/kinds/owners/locations, duplicate or ambiguous results and honest partial coverage. Zoxide and ripgrep have passed the full selected-file table/key inventory (201 declaration locations in seven original TOML files), without validating TOML value semantics or every owner relation. Oracle Sample Schemas and Logger have passed the full selected-file direct SQL DDL inventory (20 tables/views/indexes across five original SQL files), including exclusion of dynamic SQL inside strings, without certifying embedded PL/SQL or database execution. Hasura's Terraform AlloyDB and Kubespray AWS sources passed independent full selected-file HCL block inventories (18 and 76 blocks respectively, across nine original files), including nested owners and native kinds, without assessing Terraform plans, expressions or cloud runtime. GraphQL Go and Hasura additionally passed complete selected-file inventories of 65 currently supported declarations across five original source files, including duplicate union definitions and a declaration-free anonymous query. The earlier missing `union` and `scalar` definitions were corrected in development and are covered by regression tests. GraphQL directive declarations, enum members, fragments, anonymous operations, arguments and selections were observed but are outside the current declaration inventory, not silently certified. MediatR additionally passed a complete 48-declaration C# inventory across four original files, including namespaces, types, members, generic methods and initializer-versus-declaration boundaries. The earlier installed connector misnamed three members; the current development handler returned the independently expected names. Humanizer also passed a complete selected-file inventory of 100 C# declarations in three original files; the installed connector fabricated primary-constructor parameter fields and misnamed two initialized fields, but the development handler returned the original names without extra declarations. The original attrs Python validators and converters also passed complete selected-file inventories of 89 function, class, method, module-variable and class-field declarations, including four nested alternatives in two converter functions. The installed connector omitted 23 supported assignments that are present in the current development handler; these were independently confirmed from the original files, not treated as false symbols. Optparse-applicative additionally passed a full selected-file inventory of 38 Haskell module, top-level function and data declarations in four original files. The stricter test exposed five false modules from export-list reexports; a focused development parser fix and positive/negative original and synthetic checks now reject these without losing real module declarations. Local `let`/`where` bindings and semantic module linking are outside this top-level inventory. CodeIgniter additionally passed a full five-file selected PHP inventory of 27 namespace, class, property and method declarations; a route method invocation was correctly excluded. Swift's compiler and Exercism sources passed complete selected-file inventories of 19 and 32 declared symbols respectively across eight original files, after genuine RED/GREEN repairs: the compiler's missing `nonisolated(unsafe)` property, two enum cases and two directly nested local functions in the Exercism exemplar. The development handler now exposes these with correct owners and lines. Conditional compilation semantics, arbitrary local variables and deeper control-flow/closure scopes are not certified. Scala XML additionally passed 87 independently inventoried package/type/member declarations across four fully read original files. Source-derived RED/GREEN testing repaired multiline class and method scopes, scoped access modifiers such as `private[xml]`, and symbolic method names such as `%`, preventing local statements from appearing as object fields or methods. Function-local declarations and Scala compiler/type resolution remain out of this selected member-level gate. WordPress additionally passed a source-first, three-file inventory of 74 top-level functions, classes, properties, methods and a constructor (normalized to its owner class), excluding function-local static variables and ordinary global statements; both original PHP navigation cases remain green without changing the parser. Go fsnotify and Gorilla mux additionally passed full eight-file declaration comparisons of 191 and 252 package, type, field, interface, constant, variable and callable locations. A separate Go standard-library syntax-tree walk over all the completely read original sources independently assembled names, kinds, owners and lines, including the Linux and Windows fsnotify backends and Gorilla's router tests. The development handler matched these without extra declarations. This validates syntax projection for the selected files, not platform-specific build semantics, real request routing or file-watcher operation. FastAPI additionally passed a source-first two-file inventory of 43 top-level helper functions, parameter classes, direct methods and class fields, including annotated dataclass attributes. Multiline function parameters, docstring examples and method-local assignments were excluded as non-declarations. The development handler matched all 43 locations, names, kinds and owners. The other two project cases (Aeson and Scala os-lib) still need the stricter audit. Keep these verification gates distinct.

For each new provider, begin with a real maintenance question and independently inspect relevant original source, tests, neighboring components, and a plausible distractor. Then verify bounded `source_symbols`/`source_query` navigation and fingerprint-bound source excerpts against direct reads and `grep_text_files`. A selected PASS does not certify a whole grammar, hidden dependencies, or the LLM's eventual edit. Keep missing original fixtures and partial coverage separate from passing cases. Use the [project-first qualification checklist](DEVELOPMENT_CHECKLIST.md#source-intelligence-project-first-qualification) for the procedure and acceptance rules.

### Shared parser families for targeted repairs

### Known limitations and verification boundaries

These caveats describe **current development-tree behavior and unresolved work**, not a list of completed language campaigns. Resolved parser changes belong in the [Unreleased changelog](../CHANGELOG.md#unreleased); the [capability matrix](LANGUAGE_CAPABILITIES.md) and [tool reference](../TOOLS.md#source_symbols) describe supported navigation.

- **Selected scope is not full grammar coverage.** Even a completely inventoried selected file does not prove unrelated files, every language construct, full ownership semantics, inferred relations, or runtime correctness. In GraphQL, directive definitions, enum value members and fragment definitions are not projected as declarations, and anonymous operations, arguments and query selections are likewise excluded from the selected supported-declaration inventory. A successful `coverageComplete` result means the requested files were processed within the analyzer's declared scope, not that all declarations, call sites, or dependencies were found. Some larger original Lua and D files, MQL4 server scripts, and complex VHDL forms remain partially supported. A shell script with no function declarations can legitimately return no symbols. Keep partial or excluded files distinct from passing maintenance scenarios.
- **Large Zig source files may remain partially indexed.** In the original zmx project, `src/main.zig` reports incomplete selected-file coverage. The qualified navigation task uses the narrower configuration, POSIX helper, test-entry, and unrelated-label scope, with an independent direct read of the main entry point; it does not claim complete indexing of the larger file.
- **Some component forms remain conservatively partial.** Vue 2 Options API methods and computed properties (for example `sortgroupcity`) remain an unverified current-HEAD gap. Svelte 5 direct object-destructured `$props` bindings (for example `copyCode`) are now indexed in the development source, including aliases, defaults and rest bindings; nested/computed patterns are not fully inferred. The selected Vue/Svelte tasks do not prove complete component APIs or browser behavior.
- **Some language constructs are intentionally conservative.** Scala XML's selected 87-declaration audit covers package, type and type-member declarations, not function-local declarations (including local classes/objects and nested functions), macro expansion or Scala compiler semantics. Swift enum cases and directly nested local function declarations are now indexed, but local declarations inside deeper control-flow or closure scopes, arbitrary function-local variables, conditional compilation semantics and full Swift grammar are not certified; `coverageComplete` must not be interpreted as compiler validation. Nested or macro-generated Common Lisp/Clojure/Emacs Lisp forms, advanced D and Lua syntax, complex VHDL types, ambiguous Ruby method bodies, preprocessor directives, generic/type inference, and dynamic dispatch are not universally resolved. Do not manufacture symbols, ownership, callable bodies, or project-wide dependencies where analysis lacks evidence.
- **Structural links are not execution semantics.** Adjacent Go/TypeScript/R/PHP code, XML/MSBuild imports, GraphQL resolvers, stylesheet consumers, HTML code-behind, and configuration overrides may be inspected directly, but providers do not automatically establish every cross-file semantic relationship. No original-project execution, compilation, database query, cloud operation, UI rendering, numerical simulation, or runtime correctness is certified by this milestone.
- **Development and installed servers differ.** An installed 4.0.1 connector may predate Git changes. Confirm discrepancies against current development handlers rather than treating an older result as a current-HEAD defect. Fingerprint-bound `show` can correctly refuse oversized source regions with `LIMIT`; narrow the requested declaration or use an authorized targeted source read instead of silently raising resource bounds.
