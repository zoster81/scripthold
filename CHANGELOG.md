# Changelog

This changelog records user-visible Scripthold changes. Detailed implementation history remains available in Git.

## Unreleased

### Fixed

- Project source-query models now make an independent copy of each retained symbol's mutable modifiers and optional source ranges. Changes to caller-owned analysis facts after model construction can no longer alter those symbol records; public search results, indexes, and source-fingerprint checks remain unchanged.
- `source_query.context` now bounds ancestry traversal when normalized source facts contain self-referential or cyclic parent IDs. Malformed ownership can no longer make context planning loop indefinitely; ordinary hierarchies, deterministic results, output budgets, and cancellation remain unchanged.
- Durable task stores can now reopen after `MCP_TASK_MAX_CONCURRENCY` changes between coordinated process restarts (for example, 4 to 8 or 12, then back to 4). Worker concurrency is a validated startup setting; existing descriptor bytes, stored task identities, and durable queue/log/runtime/retention policy remain unchanged. Running workers are not reconfigured live, and published 4.1.0 does not include this change.

### Changed

- `source_query.context` skips temporary relation-graph sorting and indexing when a project contains no structural reference edges. Reverse import dependents and cancellation still use the established bounded plan, with unchanged public context results and source-fingerprint checks.
- Path-selected `source_query.context` now borrows already sorted, parentless immutable project symbol records instead of rebuilding a parent-kind map and full copied root array. Unsorted or nested records retain the original filtered, sorted result; source fingerprints, context budgets, ordering, and public responses are unchanged.
- Recursive workspace traversal now prepares normalized authorized roots once per walk instead of repeating Windows long-path normalization for every entry. Each file and directory is still freshly resolved and checked against the allowed roots, including junction and reparse-point boundaries; ordering, filtering, and public tool results remain unchanged.
- Incremental `source_query` project-index refreshes now reuse immutable, sorted symbol records for unchanged source files instead of rebuilding those records on every generation. Global symbol indexes and cross-file relationships are still reconstructed to reflect changes; source fingerprints, language-registry changes, cancellation, stale generation selection, deterministic ordering, and public responses retain their safeguards.
- `source_query.context` now visits each target file's root declarations at most once during direct-dependency planning, avoiding repeated symbol lookups for multiple imports from the same file. The first dependency's evidence, deterministic candidate order, context budgets, fingerprints, and public results are preserved.
- `source_query.context` now borrows the existing immutable, sorted project-symbol records when a dependency file contains only top-level declarations, rather than rebuilding an identical root-symbol slice and parent-kind map for each plan. Nested and malformed-parent files retain the original filtering path; ordering, fingerprints, context limits, and public responses are unchanged.
- Source Symbols and Source Query response-size checks now use their existing legacy JSON serializers directly instead of passing the same JSON through a second encoder. This reduces response processing time on large outputs while preserving exact byte limits, Unicode escaping, error handling, and public JSON. Other value types retain the existing counting encoder.
- Concise `source_symbols` digest and outline now retain only the parent facts needed to establish top-level declarations. Owner-filtered concise outlines skip the unnecessary ancestry index entirely. Large source files use less temporary memory without changing owner selection, nested declarations, incomplete ancestry handling, truncation, or public responses.
- Repeated `source_query` requests now reuse a single per-handler fingerprint of the immutable language registry and effective analysis limits. This avoids redundant hashing and temporary allocations; changing the registry or any fact-affecting limit triggers recalculation. Source-content fingerprint checks, index generations, stale bindings, limits and public responses are unchanged.
- Refreshed pinned CI and publication tooling (Node.js 26.13.1, GoReleaser 2.20.3, golangci-lint 2.15.0, govulncheck 1.10.0, and MCP Registry publisher 1.8.11) and updated indirect Go module dependencies. Immutable Action digests and release-tool integrity checks remain enforced; this development-only update does not publish or install a new server.
- Sparse exact `source_query.search` requests with symbol-kind filters now reuse existing immutable name and qualified-name indexes rather than scanning every project symbol. Small projects, dense matches, and original source-spelling aliases retain the established scan; result ordering, evidence filters, continuation, limits, and public JSON remain unchanged. Prefix, contains, and unfiltered searches keep their previous behavior.
- Exact `source_query.search` requests with symbol-kind filters now check whether a symbol name matches before checking its kind. This improves sparse exact searches without changing original source spellings, result ordering, continuation, output limits or public JSON. Prefix and contains searches retain their previous filtering order.
- Structural `source_query.search` now delays result-heap allocation until the first match. With result limits of 16 or more, it holds one match before expanding to the original bounded top-K capacity when another match arrives. This reduces temporary memory for empty and single-hit searches while preserving public JSON, ordering, continuation cursors, truncation, and output limits.
- `source_query.context` planning now uses request-local composite keys and compact parent-kind lookups instead of concatenated keys or full symbol-record copies. This reduces allocations for repeated imports and related declarations without changing public results, ordering, limits, or source-fingerprint checks.
- `source_symbols.outline` with `presentation: "compact"` skips the ancestor lookup needed only by tree output. This avoids unnecessary temporary allocations while preserving symbol order, public fields, output limits, and the separate tree/detailed presentations.
- `source_symbols.outline` with `presentation: "tree"` now skips its ancestor index when no declaration has a parent. Flat outlines allocate less temporary memory while preserving nested tree ownership, symbol order, limits, and public JSON.
- Source Symbols output-budget validation now counts the same encoded JSON bytes without retaining an extra copy of the complete response. This reduces temporary allocations on larger results while preserving exact byte limits, escaping, errors, and public response data.
- `source_query` now reuses the same byte-accurate JSON budget counter across search, relationships, and context responses. This avoids an extra disposable JSON buffer while preserving exact output limits and existing concise/detailed response formats.
- Unfiltered `source_symbols.outline` now reserves only the bounded space needed for analyzed declarations instead of repeatedly growing its result array. This reduces temporary memory use without changing symbols, filters, truncation, fingerprints, or the JSON response.
- Source-position selectors in `source_query` now reuse a bounded, immutable file-to-reference index built with each project model. This avoids scanning and normalizing unrelated source paths on every relation or context lookup, while preserving source identity, first-match order, fingerprint checks, and public results.
- Dense per-file project relationship resolution now reuses short-lived, source-specific candidate groups rather than repeatedly scanning every declaration for each reference. This improves project model construction while keeping the same relationship evidence, ordering, ambiguity and output.
- Same-file relationship target lookup now reuses existing symbol indexes when a target has at most one indexed candidate, instead of scanning a large source file. Other lookups retain their original local scan to protect ambiguous matches and result ordering.
- Symbol-ID lookups in dense project files now use a bounded, immutable per-file index, speeding up source-query symbol navigation and related context planning. Small files retain their original scan; duplicate IDs, candidate ordering, and source-fingerprint checks keep their existing behavior.
- Context planning for larger projects now uses existing source-reference indexes to inspect inheritance and implementation relations only for selected source files, instead of scanning the entire project. Smaller projects retain the original scan; ordering, duplicate symbol IDs, evidence and output limits remain unchanged.
- Inheritance queries in larger projects now use a bounded, immutable source-symbol reference index instead of scanning every project reference. Smaller projects keep their original direct scan; cross-file duplicate symbol IDs, results, ordering, evidence and public response formats remain unchanged.
- Dense project reference models now retain compact reverse-target indexes and reuse immutable resolved-definition arrays instead of duplicating full reference records and candidate lists. Smaller projects and repeated reference identities keep their existing ordered buckets; returned definitions and references remain independent snapshots, with unchanged ambiguity, evidence, source-fingerprint checks, and relation/context responses.

## 4.1.0 - 2026-11-20

### Added

- OpenAPI source navigation now indexes `operationId` declarations only when they belong directly to a named HTTP method under `paths`, not when an identically spelled key is a reference in `components.links`, a response Link Object, or a nested schema/example. Methods without an authored `operationId` retain their existing `HTTP VERB /path` fallback navigation. The complete official OpenAPI Specification Link Object example (six HTTP operations, three schemas, four non-declaration link references) and LF/CRLF negative cases verify the distinction through native outline and fingerprint-verified handler navigation.

- Elixir source navigation now exposes directly authored single-target `defimpl Protocol.Name, for: Target.Name do` declarations as lexical `implementation` owners (`nativeKind: defimpl`) and attaches their function clauses to those exact source-owned containers. It does not expand macros, resolve protocol dispatch or target aliases, or fabricate owners for multi-target/quoted/generated implementations. The complete independently pinned Elixir `String.Chars` original (five implementation blocks, seven implementation clauses) and Phoenix HTML `FormData` original (one implementation, seven clauses) verify source names, ownership, ranges, LF/CRLF, and conservative exclusions; existing Phoenix quoted-code false-positive controls remain intact.

- GraphQL named operations with up to four directly authored **argument-free** operation directives (such as `query Name @onQuery { ... }`) now keep the complete lexically paired selection in their source declaration and signature ranges. The same bounded lexical subset also accepts one argument-free `@name` annotation on each supported variable declaration, including multiline signatures. Operation directive calls with arguments, unsupported nested or quoted variable defaults, malformed and oversized headers, and unclosed selections continue to return header-only excerpts; no GraphQL directives or variables are executed and query-selection fields are not indexed. The complete independent GraphQL.js kitchen-sink original verifies three named operations, one fragment and two anonymous negative controls, including LF/CRLF, malformed/oversized negative cases, and handler `outline`/`find`/fingerprint-bound `show`.

- GraphQL simple top-level named operations now also preserve their complete source selection block after a **bounded lexical variable-definition header** such as `query Name($id: ID!, $limit: Int = 10) { ... }`. This earlier increment recognized comma-separated direct `$name: Type` entries (up to 16), optional non-null/one-level list notation, and simple enum/numeric defaults within a 256-byte operation-header gap and a 512-byte variable scan; the later argument-free directive subset above extends source excerpts without providing directive evaluation. It preserves the previous 16 KiB/128-line source-excerpt limits and did not expand unclosed, malformed, nested-default, directive-bearing, or oversized headers; the later restricted argument-free directive enhancement above now handles a small subset; no variables are evaluated and no query-selection fields are indexed. The independent full GraphQL-Go kitchen-sink original checks its authored query (lines 3–22), mutation (24–30), subscription (32–43), fragment (45–47) and anonymous selection negative control, with LF/CRLF, bounded malformed negatives, and handler `outline`/`find`/fingerprint-verified `show` checks.

- GraphQL named `query`, `mutation`, and `subscription` declarations with a directly attached, completely paired selection block now retain that authored block in their source declaration and signature ranges, rather than returning only the operation name. This conservative lexical extension applies only to simple top-level `operation Name { ... }` forms and bounds whitespace before the brace (256 bytes), complete excerpts (16 KiB), and physical lines (128); variable-argument headers were outside that first increment (a later bounded subset is described above); directive headers, malformed, unclosed, nested, and oversized forms still keep the header-only excerpt. Exact whole original graphql-client named queries, LF/CRLF, independent fragment controls, malformed/oversized negatives, and handler `outline`/`find`/fingerprint-bound `show` navigation verify the bounded behavior. It does not parse query-selection semantics or execute operations.

- Nix source navigation now exposes simple directly authored `inherit name;`, `inherit (source) name;`, and bounded multiline `inherit (source) names ... ;` clauses within an outer `let` as source-owned variables (`nativeKind: inherited-binding`). It retains exact authored name ranges, sibling bindings, original formatting, and incomplete-coverage warnings for unmodeled source resolution, nested attributes, or other expression grammar; no Nix expression is evaluated. Complete pinned flake-parts `transposition.nix` verifies five inherited names, while LF/CRLF, malformed and oversized clauses, nested-source negatives, and original `outline`/`find`/fingerprint-bound `show` navigation qualify the conservative subset.

- C++/CLI source outlines now also recognize directly authored, lexically paired managed `property Type Name { get/set ... }` blocks as owned `property` symbols (`nativeKind: block-property`). The bounded C++/CLI adapter preserves source coordinates and attaches previously flattened getter/setter methods to their actual property owner without modifying the shared C++ analyzer. Complete original PhysX.Net `Actor.h` yields nine block-property nodes and thirteen owned accessor declarations, while independent libyara.NET `Meta.h` simple properties and unrelated methods remain intact. Original-source handler navigation, LF/CRLF and malformed-header negative tests cover this limited syntax; it is not full C++/CLI grammar or semantic accessor validation.

- C++/CLI source outlines now distinguish directly authored simple managed `property Type Name;` declarations from ordinary fields, returning an owned `property` symbol (`nativeKind: simple-property`) with the existing exact source range. The bounded correction reuses scanner-recognized field declarations without inventing symbols or changing ordinary C++ fields. Full original libyara.NET `Meta.h` and PhysX.Net `Actor.h` sources, LF/CRLF and negative field controls validate this limited form. That earlier simple-property correction did not itself model `get`/`set` ownership; the later block-property improvement documented above adds a bounded subset without claiming full C++/CLI grammar.

- C# source outlines now expose directly authored enum members as owned `constant` symbols (`nativeKind: enum-value`), with their own source/name/signature ranges and a stable parent link to the enum. The bounded lexer separates members only at enum-level commas, preserving optional attributes, nested initializer expressions, empty enums and neighboring declarations. Original Serilog `LogEventLevel` now yields its six authored values without evaluating expressions or interpreting runtime enum semantics; LF/CRLF, nested-comma and original-source navigation checks cover this structural subset. This does not provide full C# grammar, preprocessing or semantic validation.

- `source_query.context` adds opt-in `presentation: "concise"` for fingerprint-verified bounded code excerpts. It preserves the original item order, entity fingerprint and source range, selection reason, body/signature representation, evidence, resolution and UTF-8 byte accounting, while omitting repeated index inventory and internal priority values. `prefer` and `signatures-only` retain their original planning, all-or-error target selection, limits and freshness protection; legacy responses remain unchanged. Public MCP tests verify exact decoded source, structured/text parity, historical matching, body/signature policy and stale conflicts. Two independent original Java project methods passed source-first selection and byte-size comparisons; other providers remain unqualified for the new response contract.
- `source_query.relations` adds opt-in `presentation: "concise"` for all nine supported structural relation kinds, without changing index computation or historical outputs. It preserves exact source and target identities/ranges, evidence, resolution and exceptional edge kinds, while omitting repeated per-edge relation names and current-index bookkeeping. Empty, partial, truncated, ambiguous and retained-stale states remain explicit. Public MCP tests covered all nine kinds, verified source-site evidence and response/text parity. Original cross-file Solidity and Groovy projects passed the selected dependency projections; more provider-level original-project coverage is pending.
- Structural `source_query.search` adds opt-in `presentation: "concise"` without changing legacy results or the project index. It groups source-verifiable hits per file, keeps distinct declaration IDs and structural reference-site evidence, reports only non-redundant index data, and separates cursor pagination from incomplete analysis. Explicit encoding is available for safe follow-up when supplied by the caller; otherwise the result does not invent it. The public MCP client verifies 3-page continuation, overloads, cross-file reference sites and legacy output. Two independent original Java projects passed concise search-to-show oracles with measured response-byte reductions; other providers remain to be qualified.
- Source Intelligence adds opt-in `presentation: "concise"` for all four `source_symbols` operations (`digest`, `outline`, `find`, `show`). Digest maps file-level classes, types and functions, including recognized non-public declarations, without repetitive counts or fingerprints. A concise outline can select a class by exact `owner` name and returns recognized private/public methods, constructors and distinguishable overloads, omitting fields unless explicitly requested. Multiple same-name owners remain separate and ambiguous; partial analysis, file selection and result limits are reported independently. The concise `find` groups matching declarations per file and retains the full symbol ID plus a single file fingerprint, language and encoding for safe `show` navigation. Concise `show` returns the exact selected declaration, signature or body range with decoded text and an explicit completeness flag, rejecting unavailable body/signature ranges rather than silently substituting a header; its text and structured MCP results agree. Historical output layouts and defaults remain unchanged. Real MCP-client regressions and two original Java project source-oracle tests passed; other providers remain unqualified for this response contract.
- QBasic and classic BASIC numbered source lines are now navigable as `label` declarations with `nativeKind: line-number`. Exact `source_symbols find` and structural `source_query search` locate source line numbers, and fingerprint-bound `show` retrieves the authored statement. Existing declarations take priority under symbol limits, and numeric expressions after `:` are not mistaken for new labels. This is structural navigation, not `GOTO`/`GOSUB` resolution or program execution; focused LF/CRLF regressions and two original classic BASIC projects check selected behavior.
- SQL source navigation now finds named `CREATE INDEX` and `CREATE UNIQUE INDEX` objects, including common `IF NOT EXISTS` and `USING` forms, as `resource` declarations with `nativeKind: index`. Index headers must identify a table and column list; unsupported forms report incomplete coverage instead of inventing indexes. SQL execution and database schema resolution remain unavailable.
- Assembly source navigation now finds MASM/Motorola `NAME EQU value` constants, named MASM/NASM `DB`/`DW` data, and named Motorola 68HC11 `FCB`/`FCC`/`FDB`/`RMB` data declarations outside recognized macro/structure definitions. `FCB`/`FDB` operands must be present, `RMB` requires one storage-size expression, and `FCC` strings must use matching delimiters; this is structural navigation, not assembler expression evaluation or macro expansion.
